# APKの固定署名

このプロジェクトのデバッグAPKはGitHub Actionsでビルドします。GitHub Actionsの実行環境は毎回使い捨てのため、固定鍵を登録しないとAPKに別の署名が付いてしまいます。

## 初回の設定

1. あらかじめ安全に保管した署名用キーストア（PKCS#12）を用意します。**鍵そのもの、Base64文字列、パスワードをGitのソースやIssueに書かないでください。**
2. GitHubリポジトリの **Settings → Secrets and variables → Actions → New repository secret** を開きます。
3. `HISSI_KEYSTORE_B64` を登録します。値はキーストアの全バイトをBase64にしたテキスト（折り返しなし）です。
4. `HISSI_KEYSTORE_PASSWORD` を登録します。キーストアを生成したときのパスワードです。
5. キーのエイリアスは `hissi-checker-droid` に固定します。キーのパスワードはストアと同一にします。
6. GitHub Actionsのビルドを実行し、「Persistent signing keystore restored.」が記録されることを確認します。

鍵が設定されている場合、Gradleのdebugビルドでは同じ署名が使用されます。登録がない場合、ワークフローは警告を表示し、従来の一時的なデバッグ署名でビルドします。

## 保管と運用

- **キーストアとパスワードを必ず安全な場所にバックアップ**してください。鍵を失うと、同じパッケージ名での上書き更新はできません。
- GitHub Secretの変更だけで既存アプリの署名と一致するわけではありません。**固定署名への初回切り替えでは、従来のAPKを一度だけアンインストールする必要があります。** 設定やデータも削除される場合があります。
- 初回の切り替え後は、同一の署名鍵と、増加する `versionCode` を維持することで上書き更新できます。
- 公開用リリースであれば、デバッグ用と区別した正式な署名鍵の運用を検討してください。
- 署名の一致は `apksigner verify --print-certs app-debug.apk` の証明書SHA-256で確認できます。
- 今回準備した固定鍵の公開証明書SHA-256：`C9:08:66:1A:C6:52:2B:03:1D:8E:1F:BC:6E:04:19:4B:77:47:88:F3:71:61:E4:B9:79:D9:41:C4:A8:0B:7C:2C`（この値は秘密情報ではありません）。

**重要:** GitHub Actions Secretsの登録操作は、リポジトリの管理者権限でGitHub画面から実施してください。ビルド成功のみで固定署名の登録完了を意味しません。

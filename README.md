# 必死チェッカーdroid +

**Hissi Checker Droid Plus**

## 概要

「必死チェッカーdroid +」は、5chのID別書き込みを、**レス・スレ・名前**の3つの視点で確認するAndroidアプリです。オリジナルAPKの機能を出発点に、表示密度、操作性、通信・解析処理の改善を進めています。

- **オリジナルAPK v1.5を基準とした独立再構築版**です。
- プロジェクト名は **Hissi Checker Droid Plus**（リポジトリ名：`hissi-checker-droid-plus`）、アプリの表示名は **必死チェッカーdroid +** です。

## 主な機能

| 分類 | 内容 |
| :-- | :-- |
| **5ch検索** | 板・日付・IDを指定して必死チェッカーの結果を表示。`ID:` / `ID：` 付きの入力も受け付けます。 |
| **板一覧** | [5ch公式メニュー](https://menu.5ch.io/bbsmenu.html)を参照し、**カテゴリ → 板**の順で選択。公式JSONを優先し、取得失敗時はHTML・保存データなどへフォールバックします。 |
| **結果の3タブ** | レス / スレ / 名前。**下線式タブ**をタップ、または左右にスワイプして切り替えます。 |
| **レス一覧** | 余白と装飾を抑えたダークUI。大きなカードは使わず、細い区切り線でレスを表示します。 |
| **スレ一覧** | 同じスレッドをURL末尾のレス番号の違いに左右されず集約します。 |
| **レス操作** | レスをタップすると中央に操作ダイアログを表示。常設のコピー・共有ボタンは置きません。 |
| **ChMate連携** | 対応リンク・テキスト共有（`text/*`）から結果画面を直接起動し、戻る操作で呼び出し元へ戻る構成です。 |
| **エッヂ（試験対応）** | URL認識、専用解析処理、WebViewとHTTPのCookie共有・診断機能を実装。ただし、**実サイトからのレス取得は未確認・アクセス拒否の問題が残っています**。 |

### レスの操作・コピー

レスをタップすると、以下の操作を選べます。

| 操作 | コピーする内容 |
| :-- | :-- |
| スレを開く | 対応スレッドを開きます。 |
| **スレタイと全体をコピー** | スレタイ → レスURL → **レス番号から始まる投稿情報** → 本文 |
| **全体をコピー** | **レス番号から始まる投稿情報** → 本文 |
| **スレタイと全体を追加コピー** | 現在のクリップボードに、スレタイ・URLを含む内容を追記 |
| **全体を追加コピー** | 現在のクリップボードに、投稿情報と本文を追記 |
| **IDをコピー** | 投稿のIDを `ID:xxxx` 形式でコピー。 |
| **リンクをコピー** | レスURLをコピー |

コピーした文章では、空のメール欄を `[]` として表示せず、不要な区切り文字・連続スペースを整理します。Android 13以降はOS側のクリップボード通知との二重表示を抑制します。

## UIの方針

- ダークテーマを基準に、アクセントカラーは **`#00B8AF`**。タイトルの「droid +」にも適用します。
- タブは**選択中の項目にだけ下線**を表示。塗りつぶしや枠線付きのタブにはしません。
- レス表示は細い区切り線とコンパクトな余白を使い、画面内の情報量を優先します。
- ダイアログは**画面中央・角丸・テーマに沿った配色**に統一。下から出るシート型は使いません。
- アイコンはオリジナルの顔文字を基準に、「+」と `HISSICheckerDroid+` を加えた構成とします。

### ローカルビルド

JDK 17、Android SDK 36、Gradle 9.8.2が必要です。

```bash
gradle --no-daemon :app:testDebugUnitTest :app:assembleDebug
```

生成されたデバッグAPKは `app/build/outputs/apk/debug/` に保存されます。Gradle Wrapperは現時点で同梱していません。

Privateリポジトリでは、mainのGitHub Actionsでビルド・検証しています。固定APK署名を使うには、[署名設定手順](docs/SIGNING.md)に従ってリポジトリのActions Secretsを登録してください。未登録の場合、従来どおり一時的なデバッグ署名となり、APKの上書き更新はできません。**Release・一般公開は実施していません**。

## エッヂ MHT の解析について

2026年10月22日にブラウザ保存された実際のエッヂ必死チェッカーページを調査し、HTMLの `Shift_JIS`、`.box.content > .post`、`.r-head` と投稿本文のテキストノード構造を確認しました。保存ページのレス65件・スレ7件を参考に**匿名化した構造テスト**を用意しています。実データをGitHub上へ登録していません。

HTTP応答からステータスコード・Content-Type・文字コード・リダイレクト回数・Cookie送信の有無を、IDや本文を含まずに診断できるようにしています。ブラウザでは表示できてもアプリにHTTP 403が返る可能性があり、**正常取得を保証するものではありません**。

## v0.1.21 の修正点

- 5chレス一覧のHTML解析に、複数の `dt/dd` 構造と見出しの違いに対応する処理を追加（実サイトでの動作再確認が必要）。
- エラー詳細は長押しで文字選択・コピーが可能。右上メニューの解析情報コピーを廃止。
- スレ・名前一覧に取得済みの投稿回数を ` (件数)` で表示。コピー内容は従来のスレ名・名前のみ。

## 検索履歴

検索結果を正常に取得した場合、5ch・エッヂの直近100件を端末内に保存します。お気に入りは履歴とは独立して管理され、100件の履歴上限によって削除されません。右上メニューの「検索履歴」から再表示、履歴とお気に入りの切り替え、☆／★登録とソート（新しい順／古い順／板名順／対象日順）ができます。履歴データは端末外に同期しません。

5chの時間帯別投稿数グラフは各レスの時刻から計算し、初期状態で展開します。5chのHTMLがUTF-8と宣言されていても実バイト列がShift_JISの場合には再判定します。ただし元HTML内の「�」のようにすでに失われた文字は復元できません。

## v0.1.21: エッヂの書き込み分析

エッヂ検索結果の「書き込み分析」からサイト提供の分析を参照します。未分析時にはユーザーが「分析を開始」を押したときだけWebViewでサイトの分析ボタンをクリックします。サイト側の認証・アクセス制限や仕様変更がある場合は、外部ブラウザでの操作が必要です。アプリ独自のAI分析・自動分析は実施しません。

5chの順位表記、検索履歴の日付と中央揃え、各テーマでのボタンと入力欄の差別化も改善しました。

## v0.1.21 / 操作性・検索改善

- 5chのカテゴリ一覧は公式JSONまたはHTMLを初回のみ取得して端末に保存。以降は端末内キャッシュから即時表示し、カテゴリダイアログ右上「⟳」で明示的に更新できます。更新失敗時は保存済みの板一覧を維持します。
- 履歴に表示順の項番、長押し削除、複数選択による削除、通常履歴の全削除を追加。お気に入りは100件とは別に保存し、通常履歴削除では解除しません。
- エッヂには板（既定：liveedge）、日付、IDの検索欄を追加。サイトの公式検索フォーム（ID・日付一致）で投稿を検索し、**対象スレッドをユーザーが選択したときのみ、そのスレッドキーから必死チェッカーURLを生成**します。ID・日付だけでスレッドキーを推測しません。以前のURL貼り付け機能も残しています。サイト側の検索画面が利用できない場合、外部ブラウザから確認できます。
- 書き込み分析はセクションごとにカード分けし、評価はラベル／値、分類は割合バー、説明は改行テキストとして表示。未知のセクションは本文を省略せずに表示する方針です。自動分析は実行しません。

## ChMate連携について

Android 12以降、外部板のURLをChMateで直接開けるかはChMate側の公開Intentフィルターに依存します。エッヂをChMateが直接受け付ける場合のみそのIntentを使用します。対応しない端末・版では、スレッドURLをコピーしてChMateを起動する方法と、外部ブラウザで開く方法から選択できます。ChMate未インストールなら既定ブラウザで開きます。アプリ側からChMateの「URLを指定して開く」画面に直接値を入力することはできません。

## 正規リリース前QA（開発版）

ChMateがインストールされている場合、ADBで検証した明示的Activityの起動方法を維持します。未インストール時は、URLを受け付ける掲示板専用アプリを優先します。対応先が1件なら直接開き、複数ならアプリ選択画面、該当なしならブラウザで開きます。一般ブラウザの誤検出対策を実装していますが、Android 8/14/16での実機回帰は別途必要です。

QAビルドは `testDebugUnitTest` / `lintDebug` / `assembleDebug` をGitHub Actionsで実施します。正式Releaseへの移行は、実機および通信・画面の回帰確認後に行います。
